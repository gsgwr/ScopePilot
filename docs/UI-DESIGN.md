# UI構成（0.11.1）

Microsoftの[Windowsアプリ設計ガイドライン](https://learn.microsoft.com/ja-jp/windows/apps/design/guidelines-overview)と[ナビゲーションの基本](https://learn.microsoft.com/ja-jp/windows/apps/design/basics/navigation-basics)に沿い、作業の流れと記録の参照を左ナビゲーションに分ける。既存のWPFを維持し、標準コントロールに共通の配色・操作状態・フォーカス表示を適用する。

## 画面の役割

| 画面 | 主な操作 |
| --- | --- |
| 1 案件設定 | 保存済み案件を開く／新規作成、対象範囲・ロール・探索上限・参照基準を設定 |
| 2 探索 | 開始・停止、手動操作の案内、進捗とコピー可能なログ、接続準備 |
| 3 候補レビュー | 検索、採用状態で絞り込み、1クリックで採用・除外、判断根拠と注意点を参照 |
| 4 Burpへ引き渡し | Scope出力の生成・コピー、Community Editionへの手動登録案内 |
| 観測した通信 | 通信の一覧、HAR・JSONL・URL一覧の取込 |
| 診断所見 | 観測根拠・未確認事項の確認、案件レポート出力 |
| 実行履歴 | 過去の結果・制約・差分、ファイル参照、再試行・実行単位の削除 |
| データ管理 | ZIPバックアップ、容量確認、生成物の整理 |

## 操作と表示

- 本文14 DIP、見出し28 DIP。余白と主要操作の位置を統一する。
- 案件設定は縦スクロールのフォームとし、保存操作を常に画面上部に置く。
- 候補・所見・実行履歴は一覧と詳細の高さをドラッグまたはキーボードで変更できる。長い詳細は独立してスクロールする。
- 最小ウィンドウ960×700 DIP。表の列幅は保持し、収まらない場合は横スクロールする。
- Windowsのアプリテーマをタイトルバー・入力・選択・無効状態・スクロールバーに反映する。
- Ctrl+Sは案件保存、Ctrl+Fは候補レビューへ移動して検索欄にフォーカスする。
- 0件では案内を表示する。検索フィルターは選択状態を表示し、実行結果の最新メッセージを全画面共通の下部に表示する。
- 探索中は案件条件・候補判断・データ削除を無効化する。採用／除外の全解除は確認を挟む。

## 検証

`WindowLayoutTests`はユーザーの案件を読み込まず、8画面×2テーマ×2サイズ×空／データありの64構成をレイアウトし、一覧の最小高さとバインディングエラーを検査する。`SCOPEPILOT_UI_SNAPSHOTS`にフォルダーを指定すると描画画像を保存する。実機では画面切り替えとCtrl+Fによる検索を確認する。

高コントラスト配色はシステム色へ切り替えるが、スクリーンリーダー・高DPI・高コントラストの実機検証は別途必要。今回の変更で探索エンジンや診断判定の網羅性を変更したものではない。
